## Self-test

Four layers, run them in order.

```powershell
pwsh -File tools/GenerateAssets.ps1
pwsh -File tools/ValidateAssets.ps1
javac -encoding UTF-8 -cp build/classes/java/main -d build/tmp/logiccheck tools/LogicCheck.java
java -cp "build/classes/java/main;build/tmp/logiccheck" LogicCheck
pwsh -File tools/SmokeTest.ps1
```

| Layer | Coverage | Expected result |
| --- | --- | --- |
| `GenerateAssets.ps1` | Textures, models, blockstates, language files, recipes and loot tables are all generated by scripts | the assets directory is written |
| `ValidateAssets.ps1` | JSON validity, model and texture references, language placeholder counts, tooltip line counts, recipe whitelist, loot tables | `106 JSON files, 18 blocks` |
| `LogicCheck.java` | Pure logic: signal protocol, gate truth tables, scanner, comparator, clock, data conversion, variable assignment, exchange pricing | `161 checks, 0 failures` |
| `SmokeTest.ps1` | Three passes of a dedicated server, placing real blocks and asserting states, drops, command output, charts and video | every line `PASS`, no `FAIL` |

Smoke test notes:

- The three passes must run separately (pass 1 places, pass 2 asserts, pass 3 asserts after power is removed), because evaluation happens at the end of a tick;
- Every `say OK_*` marker must be registered in `$expected`, otherwise the test ran without checking anything;
- Chart and video run in passes 2 and 3, and a single source cannot start two recordings at once.

## Debug commands

```text
/circuit-debug info full-circuit             # dump every circuit block, one line of state per block
/circuit-debug test start <x> <y> <z>        # simulate a wire network in a sandbox
/circuit-debug test dead-loop <x> <y> <z>    # detect dead loops via state hashing
/circuit-debug test stop [id]                # stop a simulation
/circuit-debug run-chart <A> <B> <ticks>     # record the real world and render a chart + txt
/circuit-debug run-video <A> <B> <ticks>     # render the same recording as a GIF, plus MP4 when ffmpeg exists
```

The contract of `info full-circuit` is `<block name> (<x>, <y>, <z>) [<SNBT>]`, one block per line, no header, no merged lines.

`run-chart` and `run-video` write to `<game dir>/circuit-charts/` by default; single player also opens an in-game save-as screen. The dev client is headless, so the AWT native dialog is unavailable there.

## Code layout

```text
src/main/java/l/circuit_redstone/logic/cas/
  CircuitRedstone.java        entry: registration, initialisation, startup log
  ModRegistry.java            18 blocks, items, block entity types, item group
  block/                      block implementations (wire, gates, scanner, variable, hover block, hidden sign, ...)
  block/entity/               block entities (levels, text, variables, clock phase, colour)
  logic/                      pure logic: signal protocol, gate truth tables, scanner merge, data conversion,
                              variable assignment, exchange rules
  update/                     evaluation scheduling: dirty queue, wire network BFS, independent dust evaluation,
                              orphan block entity cleanup
  command/                    /circuit-terminal, /circuit-set, /circuit-read, /circuit-debug
  debug/                      charts, video, chart rendering and saving
  client/                     client side: colour tint, cutout render layer, hidden sign text renderer
  item/                       tooltip items, variable block item
tools/                        asset generation, asset validation, logic self-test, smoke test
docs/DEVELOPMENT.md           technical details (protocol, scheduling, limits)
```

Design conventions:

- Block update callbacks only enqueue; real evaluation happens in `END_WORLD_TICK`, so updates never recurse;
- Block state is what the client syncs and renders, block entity data is authoritative;
- Data blocks (constant, string, variable) emit no redstone and are only read and written by the scanner and data wires;
- A model must carry `parent` or `elements`, otherwise it bakes into an empty model and the block is invisible.

## Release

1. Bump `version` in `gradle.properties` (`fabric.mod.json` references it through `${version}`).
2. `gradlew build` and confirm `build/libs/circuit-redstone_logic-<version>.jar` exists.
3. Unpack the jar and check `fabric.mod.json`: `version` and `license` must be correct.
4. Create the GitHub release `v<version>` and attach the jar from `build/libs/` only. The release carries nothing else: README and LICENSE live in the repository.

The published jar must be the remapped artifact from `build/libs`; the one in `build/devlibs` only works in a dev environment.
How to tell: references to Minecraft classes must be `class_xxxx` (intermediary), not yarn names.

## Known engineering constraints

- The build JVM must be >= 25 while the bytecode target is 17; do not mix the two.
- The client is headless (`-Djava.awt.headless=true`), so save dialogs that rely on AWT do not work in the dev environment.
- `run/` is the dev run directory, shared by the client, the dedicated server and the smoke test; log files may be locked.
- Killing the Gradle client process can take the shared daemon down with it; avoid touching it while a build or a test runs.
- All assets are generated by scripts. Do not hand-edit files under `assets/` or `data/`, the next generation run overwrites them.
